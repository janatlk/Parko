# Промпт для Kimi Slides

## Задача
Создай презентацию из 10–12 слайдов для защиты дипломного проекта Parko (5 минут на разговорную часть, большой экран). Формат: широкоэкранный 16:9. Стиль: тёмная тема, оранжевые акценты (#ff9100), крупный шрифт, минимум текста на слайде, cinematic-драматургия.

## Продукт
**Parko** — SaaS-платформа для управления автопарком предприятий (fleet management). Multi-tenant (изоляция по компаниям), ролевая модель (админ, диспетчер, механик, водитель, бухгалтер). Стек: Django + DRF, React 19 + TypeScript, PostgreSQL, Groq AI (LLaMA 3.1). AI-ассистент с tool calling (может создавать записи о топливе, искать поломки, отвечать на естественном языке). Есть дашборд с аналитикой (Recharts), экспорт отчётов (PDF/XLSX/CSV), email-рассылка, тёмная тема, i18n (RU/EN/KG).

## Запреты
- НЕ делай классическую академическую структуру "Проблема → Актуальность → Цели → Задачи → Аналоги → Архитектура → ...".
- НЕ используй списки из 4–5 пунктов на слайде.
- НЕ начинай со слов "Добрый день, меня зовут...".

## Обязательное содержание (через историю)
Нужно раскрыть: проблему, актуальность, решение, ключевые фичи, архитектуру/стек, результаты. Но подавай это не как пункты, а как историю диспетчера Айбека.

## Структура слайдов

### Слайд 1. Хук (титульный)
- Заголовок: "Айбек не спал этой ночью" (крупный, жирный, по центру).
- Подзаголовок: "Потому что завтра — отчёт за квартал. А данные разбросаны по 47 таблицам."
- Внизу небольшой бейдж: "Parko · Fleet Management SaaS".
- Настроение: интрига, тёмный фон, один оранжевый акцент на цифре "47".

### Слайд 2. Проблема (08:00)
- Заголовок: "47 открытых вкладок Excel".
- Под ним: "Топливо в одной таблице. ТО — в другой. Страховки — в папке на рабочем столе. Ни одна не обновляется в реальном времени."
- Визуал: разрозненные блоки/окна, символизирующие хаос.
- **Здесь заложена проблема:** фрагментация данных, человеческий фактор.

### Слайд 3. Боль (12:30)
- Заголовок: "Страховка просрочена. Снова."
- Под ним: "Машина простаивает. Штраф. Звонки. Человеческий фактор, который невозможно устранить бумажкой на стене."
- **Актуальность:** без цифровизации учёта потери от простоя и штрафов растут экспоненциально с размером парка.

### Слайд 4. Драма (18:00)
- Заголовок: "Отчёт за месяц".
- Центр слайда: огромная цифра "≈3 часа" (оранжевая).
- Под ней: "Сбор данных. Сверка. Правка формул. Повторная сверка. Каждый месяц."
- **Это актуальность для бизнеса:** руководство принимает решения на основе данных, которые готовятся с опозданием и с ошибками.

### Слайд 5. Поворот
- Заголовок: "А если бы Айбек просто спросил?"
- Под ним: "Без таблиц. Без ручного поиска. Без страха, что что-то забыл."
- Это переход к решению.

### Слайд 6. AI в действии
- **Концепция:** показать один реальный диалог, а не список возможностей.
- Левая часть (блок диспетчера, синяя граница): «Сколько мы потратили на топливо в марте? И какой расход на Mercedes 777?»
- Правая часть (блок AI, оранжевая граница): «284 500 ₽. Расход Mercedes 777 — 12.4 л/100 км, выше нормы на 8%. Рекомендую проверить топливную систему.»
- Время ответа: мелким текстом "3 секунды".
- Ниже кратко: "Tool Calling на базе LLaMA 3.1 (Groq). Ассистент не просто отвечает — он создаёт записи, ищет поломки, строит прогнозы."

### Слайд 7. Дашборд
- Заголовок: "Всё, что важно — на одном экране".
- **Визуал:** макет дашборда (круговые диаграммы, KPI-карточки, alert'ы).
- Под ним 3 коротких тезиса без буллетов, просто строки:
  - Просроченные страховки подсвечены красным автоматически.
  - Стоимость километра считается в реальном времени.
  - Отчёт за квартал — один клик.

### Слайд 8. Цифры (результаты)
- Заголовок: "5 часов рутины → 20 минут решений".
- Три колонки с большими цифрами:
  - Слева: "5ч → 20 мин" (экономия времени диспетчера).
  - Центр: "0 → 100%" (контроль сроков страховок и ТО).
  - Справа: "12 таблиц → 1 клик" (генерация отчёта).
- **Это итог/результат внедрения.**

### Слайд 9. Архитектура (кратко, без занудства)
- Заголовок: "Что под капотом" (или "Как это работает").
- Визуал: 3 горизонтальных слоя, стилизованных под блоки.
  - Frontend: React 19, TypeScript, Vite, Mantine UI.
  - Backend: Django 4.2, DRF, JWT, PostgreSQL.
  - Intelligence: Groq API, LLaMA 3.1, SSE-стриминг.
- Под слоями один тезис: "Multi-tenant: каждый клиент изолирован на уровне company_id. Роли от COMPANY_ADMIN до DRIVER."
- **Важно:** не перегружать. Только ключевые слова, без списка библиотек.

### Слайд 10. Финал
- Заголовок: "Parko" (огромный).
- Под ним: "Автопарк, который управляет собой."
- Внизу мелким: "SaaS · Multi-tenant · Dark Mode · i18n (RU/EN/KG) · Docker-ready".

### Слайд 11. Вопросы
- Заголовок: "Вопросы?"
- Контакты: Жанузаков Жанат, IT-26, Compass College.
- GitHub/ссылка на проект.

## Дизайн-указания
- **Фон:** глубокий чёрный/графит (#0a0a0a → #141414), без текстур.
- **Акценты:** оранжевый (#ff9100) для ключевых цифр и хайлайтов, синий (#228be6) для второстепенных акцентов.
- **Типографика:** Inter или аналог. Заголовки — black/900, 48–72pt. Обычный текст — light/300, 24–32pt.
- **Принцип:** на слайде не больше 20 слов + одна цифра/визуал.
- **Переходы:** fade или none, без летающих элементов.
- **Изображения:** если используешь скриншоты, закругляй углы (border-radius) и добавляй тень.

## Тон презентации
Драматичный, но профессиональный. Как трейлер к фильму, а не как инструкция к холодильнику. Каждый слайд — это сцена в истории Айбека. Мы не говорим "система имеет следующие преимущества...", мы говорим "Айбек наконец пошёл домой к семье вовремя".
